# 合成预约闭环设计与验收边界

本例为 `synthetic`：固定假用户、假会话与假座位，独立 SQLite 服务及调用方 journal。
无模型、网络账号、校园访问或费用。例子在 `examples/synthetic_booking/`，不进入 kernel 或 wheel。
通用 API 与隐私边界遵守 [最小集成契约](external-integration.md)。

## C01：执行主体、确认与状态

业务服务从预置假会话解析主体，忽略模型自报身份的设计不够：未知字段直接拒绝。
有权限且会话未过期才可确认、执行和查询；不同主体不能查询或取消他人预约。
确认由服务生成，绑定主体、operation_id、动作、日期、座位与预约引用，限时且一次消费。
动作或参数变化必须重新确认；同 operation_id 的合法重复仅用于已有业务结果恢复。
业务查询返回受控结构化证据，任意工具返回文本不能触发另一动作或更改执行主体。

adapter 在调用前持久记录原意图和 attempted；重启后先查询原 operation_id。
查询证实成功后才记录业务成功；外部执行响应本身不作为成功依据。
支持去重且查询明确 not_found 才重发原操作；查询不可用或没有去重能力时保持 unknown，
给出不含账号/令牌的 operation_id、阶段和人工核对提示。禁止自动换 ID 重试。
业务成功而 kernel 不可用时状态为 evidence_pending，恢复只补交同一摘要，绝不重做业务动作。

取消使用独立确认和 operation_id，服务验证预约归属后执行并查询。
取消失败保留 confirmed，取消未知保留 unknown；本地 generation 回退不伪装为取消。
服务 SQLite 事务只保证模拟业务库自身原子性，与 kernel 没有共同事务。

## 威胁模型与证据

测试覆盖参数替换、主体伪造、跨用户、确认重放、过期会话、工具返回伪造与上下文混用。
adapter 只消费允许字段；kernel 摘要不含会话、确认 token、日期、座位、原始返回文本或用户名。
调用方私有 journal 保存主体/意图/确认的绑定摘要和已核验证据，0600/0700，仅限测试用户。
恢复调用必须由调用方提供原意图与原确认；摘要不是加密或匿名化，不得公开 journal。
服务和 journal 均不得被其他用户修改；同 UID 恶意进程、主机失陷及服务伪造合法结构化结果
不在本例可证明边界内。结构校验不能证明服务诚实，哈希链不能证明执行真实性。

合成服务以独立进程处理每次请求，SQLite 保留跨进程状态；不监听网络、不实现通用认证产品。
丢响应故障在业务持久化后退出子进程，恢复路径必须查询；独立重启不能依赖 adapter 内存。
只可声称工具/策略层合成验收，不可声称真实模型抗提示注入或真实校园 live 成功。
所有运行状态、日志放仓库外，运行测试前先指定独立目录；本例不自动删除测试目录。

## 验收矩阵与运行

| 范围 | 必须观察的结果 |
| --- | --- |
| C02–C04 | 真实子进程服务正常预约/查询、无余位、身份失效和无权限 |
| C03/C08 | 修改确认日期/座位/动作、伪造主体、跨用户、重放或恶意工具字段被拒绝 |
| C05/C06 | 业务已提交丢响应、重启、重复请求不重复执行；无法查询且不去重时 unknown、无自动重发 |
| C07 | 独立取消并查询；失败和未知保留，kernel generation 操作不改变业务库 |
