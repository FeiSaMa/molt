# 校园接入前置确认材料

本文仅为 D01–D03 材料，不是接入授权、对外承诺或部署记录。未联系校方或乙方，
未访问真实校园系统、账号、飞书或付费模型。D04 在有权人员确认前保持 BLOCKED。
当前可复验能力限于 [合成预约](synthetic-booking.md) 的工具/策略层。

## D01：由有权人员确认的清单

| 决策 | 必须取得的内容 | 未确认时的边界 |
| --- | --- | --- |
| 试点业务范围 | 接口 owner、预约/查询/取消范围、测试租户、测试账号、允许时段及书面授权来源 | 不调用真实业务 |
| 模型位置和能力 | 校内或批准网关、模型/工具权限、出站白名单、能力与成本预算、保留政策 | 本地模型不可用时停止，不切外部付费 API |
| 数据分级与出站 | 姓名/学号/会话/课表等分类、允许给模型的字段、受控引用、日志和备份处理方 | 不传真实敏感原文 |
| 飞书范围 | 应用权限、消息来源校验、群/私聊边界、内容经飞书外部服务的校方批准 | 不创建真实应用或发送消息 |
| 身份和账号关联 | 校园 SSO 产品、服务端 subject 来源、飞书账号映射责任、解绑/离校/冻结流程 | 不信任模型填写的用户标识 |
| 正式接口保障 | 操作幂等键、按业务 ID 查询、超时含义、配额、取消规则、错误语义与人工窗口 | 查询/去重不足时 unknown 并停止自动重试 |
| 测试和隔离 | 沙箱接口、假数据、独立凭据、网络/进程/文件权限、监控与值守 | 不借正式服务试错 |

需要校方业务 owner、身份/安全/数据责任人和乙方交付负责人分别确认其权限范围。
确认记录应带版本、范围、有效期、撤销方式与审批人角色；真实凭据不写进确认文档或仓库。

## D02：成熟身份产品的接入需求

复用经校方批准的身份提供方；不在 molt 中实现密码、TOTP、Passkey、MFA 或找回系统。
SSO 验证必须由可信后端完成，核验 issuer/audience/签名、有效期及会话撤销；
具体协议/产品/密钥轮换由身份 owner 提供，不凭当前模拟会话推断可用 API。
账号关联使用服务端验证的稳定 subject；关联、解绑和高风险重绑有独立验证与审计，
不得用模型、客户端姓名或可重用截图作为身份证明。

预约前逐次检查会话、业务权限、资源归属和确认；变更动作/日期/座位后重新确认。
确认绑定主体、规范化动作、参数摘要、有效期、一次性标识和业务操作 ID，
确认机制不能被历史聊天中的“同意”或模型输出替代。
定义 MFA 提升认证触发条件、会话撤销传播时限、离校停用、丢失设备和找回责任。
跨用户上下文、日志与缓存隔离由应用层验收；同 UID kernel socket 不是租户隔离机制。

身份产品评审至少提供以下沙箱证据：伪造或过期登录被拒绝、错误 audience/issuer 被拒绝、
他人账号不能关联或解绑、撤销后在约定时限内拒绝执行、找回或重绑不能绕过 MFA。
身份 owner 明确所选协议对应的回调校验及重放防护，不把示例中的 synthetic 主体当作 SSO 实现。

## D03：责任、预算与停用条件（待各方确认）

下表为责任分配请求，尚无真实组织接受这些职责。

| 控制面 | 建议责任角色 | 验收材料/运行责任 |
| --- | --- | --- |
| 身份与会话 | 校方身份 owner + 应用承接方 | SSO/关联/撤销测试，MFA 与找回策略 |
| 业务授权与确认 | 校方业务 owner + 乙方后端 | 最小权限、资源归属、确认绑定、撤销/过期测试 |
| 模型网关和出站 | 校方数据/安全 owner + 乙方运维 | 模型白名单、请求字段投影、网络拒绝路径、预算阈值 |
| 凭据代理与执行 | 业务接口 owner + 乙方执行层 | 服务端短期凭据、权限范围、轮换与撤销；凭据不进模型/kernel |
| 状态和证据 | molt 集成维护者 + 数据责任人 | 原 ID 恢复、审计/备份演练、允许字段、访问/留存与删除政策 |
| 运维响应 | 指定乙方值守 + 校方升级联系人 | SLO、报警、人工核对、停用和恢复审批；不能默认由个人长期值守 |

必须为身份网关、凭据管理、隔离、审计存储、备份与值守列独立预算，
明确维护期、响应时限、账号费用及上限、谁能停用、谁承担业务错误与敏感数据事件处理。
个人研发投入不自动等于承担正式服务运维或数据安全责任。

每个控制面须填写：交付责任角色、验收责任角色、日常值守角色、升级联系人角色、
预算来源及金额上限、维护起止日期、响应时限、证据引用和未决风险。
目前这些字段全部待确认；缺少责任承接或预算时不进入正式运行。
停用和恢复由约定的有权角色执行并保留受控记录，模型或 Agent 无权批准恢复。

以下任一条件出现即拒绝新业务执行：身份/授权/确认失效、出站或凭据控制失效、
业务查询/去重无法满足恢复要求、审计存储不可用、成本超限或授权到期。
已发业务结果未知时停止重发，保留最小核对信息，由指定业务 owner 核验；
业务成功但证据待写时只恢复证据，不重做业务。已核验事件与未知事件分别跟踪。
恢复前补齐必要控制并由约定角色审批；不得静默切换模型、放宽策略或转用真实账号调试。

## D04：试点启动条件

仅当授权范围、身份来源、接口语义、测试环境、数据出站、责任和停用机制均有可核验确认，
再创建具体本地试点任务并单独申请真实访问授权。本文件和 A/B/C 的“继续”均不构成该授权。
M4/M5、通用 Agent 平台、真实部署与发布仍不在本轮实施范围。
