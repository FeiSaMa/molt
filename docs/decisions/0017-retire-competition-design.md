# ADR 0017：比赛设计退出主仓库

- 状态：范围已确定；获批 v2 清单所列资产已退出当前工作树，证据见 [执行清单](../execution-todo.md)
- 日期：2026-11-19
- 关联：ADR-0015、ADR-0016

## 背景与决定

`bohack-molt` 已承担比赛归档。用户要求当前 molt 不再保留比赛设计，取代此前继续保留比赛题集、演示与本地 attic 的范围决定。本仓库聚焦 agent 工作流的状态事务、证据审计、迁移与恢复，不再维护比赛 benchmark、成本排名或自进化演示。

作出决定时，CLI、包验收与 CI 依赖比赛 demo。退出按通用事务及恢复验收替代、解除导入和打包依赖、移除获批资产的顺序进行。不重新向本仓库的 attic 搬运；不修改或假称已核验外部归档内容。

## 移除与改写范围

1. 删除确认后的本地历史归档、比赛题集、场景、shell、demo 编排与比赛展示/研究文档；完整路径以仓库外 dry-run 清单为准。
2. 改写 Python CLI 和加载入口，退出比赛专用 search、propose、calibrate、demo 及题集/候选配置接口；通用状态提交、查询、audit、checkpoint、备份恢复和显式 v1 migration 必须有独立用例。
3. 将 kernel client、CLI 契约、备份恢复、安装包测试与 CI 改为有界合成对象及 generation 的通用事务验证。保留真实 socket、崩溃恢复、幂等、错误合同和零写入验证，不以删除测试代替解耦。
4. 重写 AGENTS、CONTRIBUTING、架构、style、CODEOWNERS、PR 模板、CI 与发布打包入口，退出比赛 claim、成本比较、search/holdout 和演示页面约定。具体运行 adapter 是否仍被通用接口需要，由依赖拆解决定，不因文件名批量误删。

## 兼容与安全边界

- 不回写已经验收的 1.1.0 发行归档，不将后续清理宣称为该精确包的一部分。
- 1.1.x 的 v1 读取、语义审计及显式迁移承诺继续有效。冻结 schema 的字段与语义不能原地删除或改名；比赛资产退出与 v1 兼容读取需要解耦。若实际需要移除这些能力或改变 core 协议，必须先另定新版本与 major 契约，不能沿用 1.1.0 验收结论。
- Rust kernel 的不透明对象、单写者、持久日志提交点、同 request ID 幂等和外部 checkpoint 信任边界不变；通用 kernel 吞吐测试不属于比赛 benchmark。
- M4 judge 的实现与 M5 仍未授权，本决定不扩展到执行观察、模型能力或新的 agent 框架。
- 不删除用户 state、日志、虚拟环境、stash、外部 `bohack-molt` 或已发布的包。批量删除遵守本机规则：先输出完整 dry-run 清单，获得确认后使用可恢复方式执行。

## 验收

退出后的验收条件：主运行路径与打包不再依赖被删除资产；事务、迁移兼容、恢复、审计及错误合同验证通过；CI 采用同一新边界；README 与协作约束反映实际代码；工作区没有非预期写入。需要保留的 v1 兼容数据须单独标明用途，不作为比赛产品功能或成绩材料。
