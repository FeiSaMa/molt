# chat 演示脚本

## 3 分钟最短路径

1. 打开 `/chat/`，输入 Bearer token 连接。
2. 切到「实验问答」，提问：`当前实验索引的边界是什么？`
3. 指出消息里的 `TOOL · experiments_list` 卡片和 `TOOLS` 汇总。
4. 打开「运行能力设置」→「运行 replay probe」，等待 gate / action / archive。
5. 打开「进化目录」，说明目录资产、来源 session、evidence 和 memory 条目。

## 9 分钟完整路径

| 时间 | 操作 | 看点 |
|---|---|---|
| 0:00 | 打开 `/chat/`，展示未连接、无默认数据 | token gate，不伪造数据 |
| 0:30 | 连接设置 → 填 token | 顶栏连接状态，session 建立 |
| 1:00 | 刷新页面 → 重输 token | `待恢复` → `已恢复上次会话` |
| 1:45 | 实验问答提问索引边界 | 流式回答、Markdown、工具卡、耗时、本轮 token 用量 |
| 3:15 | 打开「运行能力设置」 | runtime、快照历史、probe、执行轨迹 |
| 3:45 | 运行 replay probe | gate / action / archive，fixture 边界 |
| 5:00 | 打开「进化目录」 | 7 项资产、过滤、source / evidence / memory |
| 6:30 | 打开「项目经验/分支回退」 | 分支图、资产目录、REPLAY；不要现场切换 |
| 7:30 | 打开运行能力设置 →「打开分支黑板」，拖动/缩放，点较早节点并回退两次 | 黑板大图：主线旁生成 `rN→rM` 新分支，分支车道用不同颜色、正交折线；消息减少、revision 增加、共享资产不删除 |
| 8:30 | 收尾 | 能改、能量、能退、能说清 |

## 演示前检查

- 服务 active，token 是最近一次重启后的值。
- 浏览器 1366×768 或 1920×1080，缩放 100%–110%。
- 提前发 2–3 条消息，跑一次 probe，打开一次进化目录，避免现场等待。
- 只展开一个侧栏面板；讲完收起。
- 演示前可在「历史会话」里两次点击删除非当前测试会话，避免列表里出现测试数据。
- 不要在演示中点击「回滚当前技能绑定」或「切换分支」，除非准备修改全局状态。
- 不要在演示中跑「通用 Agent」自动进化；它会真实调用模型并可能发布全局资产。
- 如果误点了通用 Agent，可点「停止接收」：服务端会在当前模型调用返回后取消，不写入本轮历史。

## 边界话术

- probe 是 fixture / replay，不调用 live 模型；证明的是回路，不是模型能力。
- 目录资产 ≠ 本轮已加载，也 ≠ 已采纳规则。
- 快照回滚只恢复会话本地状态，共享 Skill / MCP / memory 资产不删除。
- 停止接收是协作式取消：当前模型调用返回后停止后续工具/进化，不写入本轮历史；不会立刻掐断已经发出的 HTTP 请求。
- Memory 配额 / 复用次数没有后端 API，页面只展示条目数、来源会话和版本排序。
- 旧资产的 evidence 不会追溯补齐 probe 绑定；新提交轮次才带 `bottom_evidence`。
